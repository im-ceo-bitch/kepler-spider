# Spyder Chat — восстановление соединения и уведомлений

Патч устанавливается поверх текущего `main` после Sonic + Identity / Chat Experience. Существующие серверные маршруты, wallet, seed, E2EE, Top-250, GitHub workflow и ключи не изменяются.

## Исправления

- Серверный HTTPS-адрес теперь имеет публичное резервное значение: `https://kepler-spider.helloiumrah.workers.dev`.
- Для уже созданного Spyder ID приоритет всегда отдаётся серверу, указанному в сохранённой Keychain-идентичности. Не выполняется незаметная миграция identity между серверами.
- При открытии приложения, возобновлении после фона и входе во вкладку «Сеть» происходит автоматическое обновление соединения. Пока вкладка открыта и приложение активно, данные проверяются примерно каждые 10 секунд; при отключении — каждые 6 секунд. Одновременные запросы защищены от повторного выполнения.
- Свайп вниз на вкладке «Сеть» теперь вызывает стандартный iOS `refreshable`; отдельная иконка обновления внутри страницы удалена.
- После потери сети успешный запрос сбрасывает сообщение об ошибке. Состояние подключения не выдаётся за подтверждение доставки сообщений.
- Если ранее полученный APNs-токен не удалось отправить на сервер из-за временной недоступности, приложение повторит регистрацию после успешного переподключения. Токен сохраняется только в оперативной памяти.
- Если push ещё не включены, в подключённом чате предлагается явная кнопка включения уведомлений. Без разрешения пользователя настройка автоматически не включается.

## Проверка после обновления

1. Загрузите только новый ZIP в корень GitHub. Распаковка должна сохранить пути `Console/...` и `ci/...`, без единственной внешней папки.
2. Убедитесь, что CI скомпилировал iOS-приложение. Локальный `swiftc -frontend -parse` НЕ равен Xcode build.
3. В TestFlight откройте «Сеть» и проверьте, что предупреждение о вводе HTTPS-адреса исчезло. Нажмите на верхнее поле и проведите вниз для обновления.
4. Включите «Spyder ID → Уведомления и звуки → Сообщения и приглашения» и разрешите уведомления в iOS.
5. На двух iPhone проверьте отправку, получение и push на заблокированном устройстве. Если push не приходит, посмотрите диагностику: разрешение iOS, подписка устройства, Cloudflare→APNs и последний HTTP-ответ Apple. Без этих данных фактическую причину нельзя подтвердить.
6. Если адрес Keychain-идентичности привязан к недоступному старому серверу, резервный адрес не подменяет сервер автоматически: необходимо отдельное безопасное восстановление, без потери ключей.

## Важно

Не следует обещать «постоянный» сетевой процесс на заблокированном iPhone: iOS приостанавливает приложения. Реальные входящие уведомления обеспечиваются удалённым APNs и требуют правильных entitlement, разрешения пользователя, действующего токена, работающего Cloudflare Worker и успешной доставки Apple.
