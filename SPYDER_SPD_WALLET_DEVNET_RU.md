# Spyder Wallet — SPD Devnet: подключение и приёмка

## Установка
Загрузить `console-update-spd-devnet.zip` в корень **kepler-spider**, один ZIP за раз. Существующий `console-auto-unpack.yml` распаковывает патч; workflow-файлы не меняются. Затем собрать и установить новую версию Wallet в TestFlight. Root, его Genesis и работающие валидаторы не переустанавливать.

## Однократная настройка
1. В Root на Mac убедиться, что 4/4 процесса запущены, валидаторы согласованы, RPC-шлюз активен.
2. Настроить постоянный HTTPS hostname через Cloudflare Tunnel на **http://127.0.0.1:29080**. Порт 29100 — административный Root, не публиковать его для Wallet. Не открывать порты валидаторов наружу. Использовать только свой доверенный домен; не передавать токен сторонним сервисам. Tunnel не является децентрализацией или аудитом безопасности.
3. Root → Подключение → Показать настройки доступа Devnet. Скопировать Genesis hash и токен локально, не публиковать токен и не вставлять сид-фразу.
4. Wallet → Криптовалюта → карточка Spyder Network → Подключить SPD. Ввести HTTPS hostname, Genesis hash и токен. Нажать «Проверить и подключить». Проверка использует `/v1/status`, проверяет chain ID, Genesis, режим research Devnet и отсутствие реальных активов. Сохранение только после успешной проверки. Токен в Keychain; новый origin требует явного токена. Настройка сети также доступна в настройках кошелька и на карточке SPD.
5. Нажать «Открыть SPD» и пройти системную авторизацию. Адрес вычисляется из ключа выбранного кошелька; закрытие/блокировка приложения очищает активный адрес и состояние, не удаляя сохранённую сеть или pending envelope. Никакой повторной настройки при каждой авторизации.
6. «Получить» → подтвердить тестовую сеть → скопировать публичный адрес / QR. Не используйте этот адрес для других сетей. В Root → Казначейство отправить небольшую сумму (например 1 SPD) на этот адрес, проверить окончательное подтверждение и обновление баланса Wallet.
7. На втором тестовом кошельке открыть SPD-адрес. В первом Wallet → Отправить SPD → вставить адрес, ввести небольшую сумму, проверить реквизиты и комиссию, подписать с системной авторизацией. Убедиться, что txid, финализированный блок и балансы совпадают с показаниями сети. HTTP 202 — только очередь. Проверить сохранение pending после закрытия/повторного запуска, сверку после восстановления связи и недоступность повторной подписи при неопределённом исходе.

## Границы
- Только тестовые SPD, без USD-оценки и без Mainnet. Остальные криптовалютные маршруты и Spyder Pay не переделываются. В текущем протоколе транзакции подписывают chain ID, не Genesis: не считать повторное использование ключей между независимыми Devnet безопасным. Не использовать реальные средства.
- Сеть проверяется по ответам защищённого шлюза, не независимым light client. Один Mac остаётся общей точкой отказа. Для внешней сети нужна инфраструктура, аутентификация, аудит.
- До разрешения pending перевода блокируются новые SPD-отправки и смена конфигурации; это консервативная защита, включая другие локальные аккаунты. Временно недоступная сеть не означает нулевой баланс. Сохранённый токен не передаётся другому origin автоматически.
- Автообновление после открытия адреса раз в 15 секунд в активной разблокированной сессии; без фонового мониторинга на iOS. При большой нагрузке возможны задержки/ограничения шлюза.
- Статические проверки и парсинг Swift не заменяют сборку Xcode, Simulator и тест на iPhone. Внешний HTTPS endpoint не настроен этим ZIP. Для фактической приёмки нужны работающий Root, Wallet Gateway и TestFlight.
