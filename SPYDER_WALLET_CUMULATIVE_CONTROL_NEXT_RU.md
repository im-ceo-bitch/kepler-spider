# Spyder Wallet — накопительное обновление Control Center + Address Book

## Основа и порядок

Этот ZIP — **накопительный PATCH относительно `kepler-spider-main 3.zip`**.
Он содержит все изменения, которые сохранились в проверенной цепочке
`Chat Unified → LIVE Dual Theme (Chat Compatible) → TOP-250 → Control Center`,
и новый этап **Wallet Address Book + Activity Filters**. Файлы расположены относительно корня репозитория,
без обёрточной директории. `.github/workflows/` не изменяется.

При наличии в текущем `main` новых правок команды чата или других независимых ZIP,
этот накопительный патч **нужно сначала перебазировать на свежий main**:
сохранность изменений, добавленных после перечисленной цепочки, не гарантируется.

## Новые функции

- **Wallet Address Book**: сохранение публичного адреса, названия и сети. Каждый
  BIP-39 кошелёк получает отдельный набор контактов; максимум 150 адресов.
- Данные хранятся в **локальном Keychain** с `ThisDeviceOnly`, не синхронизируются
  в iCloud и не отправляются на сервер. Это публичные адреса, не приватные ключи.
- Bitcoin проверяется по SegWit Bech32/Bech32m checksum; Solana — Base58 и
  ровно 32 байта; Ethereum — только синтаксис `0x` + 40 hex (EIP-55 НЕ проверяется).
  Проверка адреса **не удостоверяет личность** получателя.
- Сохраняйте и выбирайте получателей из **Send Flow**. Выбор адреса автоматически
  выбирает сеть и сбрасывает сумму, чтобы нельзя было случайно отправить по
  предыдущей сети. Mainnet signing/broadcast всё ещё **НЕ реализованы**.
- В **Control Center** появился пункт «Адресная книга».
- В **Истории операций** добавлены фильтры сети и статуса и отображение доступного
  времени обновления. История остаётся read-only и зависит от внешних RPC/API.
- RU/EN, светлая и тёмная темы, поддержка Dynamic Type частично наследуются от UI.

## Безопасность / границы

- Существующая BIP-39 фраза и независимые ключи E2EE не меняются.
- Нет реальной Mainnet-отправки, fee estimation, nonce management, UTXO signing.
- Это не гарантия сохранности средств и не сертифицированный production wallet.
- При удалении приложения локальная адресная книга может быть утрачена. Экспорт
  и облачная синхронизация адресной книги сознательно не включены.
- В файл не входят произвольные новые изменения, внесённые в ветку main после
  состояния репозитория, которое доступно в этом чате.

## QA перед TestFlight

1. Убедиться, что исходная ветка соответствует ожидаемой цепочке (иначе rebase).
2. Запустить автоматическую распаковку `console-update*.zip` и проверить git diff.
3. `python -m unittest discover -s ci/tests -p 'test_*.py'`.
4. `python -m unittest discover -s tests -p 'test_*.py'`.
5. `node --test server/test/*.test.mjs` и `node --test tests/messagechain.test.mjs tests/relay.test.mjs`.
6. **Обязательно на macOS** `xcodegen generate` и `xcodebuild build` без публикации в TestFlight;
   дополнительно запустить XCTest на симуляторе с iOS 17+.
7. На iPhone: проверить создание, переключение, удаление адресов, отказ при неправильной
   сети, отмену Face ID, возврат из фона, разные wallet accounts, светлую/тёмную тему,
   iPhone 11/13 mini, Safe Area и push-сценарии Chat Unified.

Проверки в этом окружении: Swift parse и отдельный Swift validation-driver;
**полной macOS Xcode-сборки здесь нет**. Установка в production без CI и QA запрещена.
