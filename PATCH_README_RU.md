# Spyder Wallet v0.4 — накопительный ZIP

## Установка
- ZIP ставится **поверх текущего Console→Spyder Wallet v0.1** или поверх v0.2/v0.3.
- Не требуется загружать предыдущие ZIP.
- Загрузить только этот `console-update*.zip` в корень GitHub-репозитория.
- Дождаться `Console — Auto Unpack Update`, затем запустить имеющийся Intel TestFlight workflow.
- `.github/workflows` в обновлении не меняются, Bundle ID: `com.console.beta`, схема: `Console`.

## Что внутри
- Все Premium UI v0.2 + secure onboarding v0.3 без потери ресурсов.
- Trust Wallet Core 4.2.9 как локальный SPM-манифест с закрепленными SHA-256 релизных xcframework.
- Реальное локальное выведение ETH/SOL/BTC адресов из **тестовой** BIP-39 seed phrase, сохранённой в Keychain.
- Получение адреса из Keychain только после подтверждения Face ID / пароля устройства.
- Список активов и экран Receive с выбором сети, QR и копированием реального адреса.
- На главный экран не подставляются вымышленные балансы/цены; отправка средств отключена.

## Ограничения
- Это НЕ production wallet. Не вводить сид-фразу от реального кошелька и не принимать реальные депозиты.
- ETH/SOL/BTC адреса образуются от стандартных путей TrustWallet Core. Совместимость с конкретным существующим кошельком и его derivation paths нужно проверить на публичных тест-векторах.
- Предполагается пустая BIP-39 passphrase; импорт с дополнительной passphrase не поддерживается.
- Проверки checksum адресов и подписи транзакций ещё не производятся. Нет сетевых RPC, балансов, UTXO, токен-аккаунтов, газа, комиссии, истории или отправки.
- Файлы TrustWallet Core скачает Swift Package Manager на Intel GitHub Actions; это увеличивает время первого билда.
- На Linux Xcode/iOS App нельзя собрать: финальная компиляция требует успешной GitHub Actions сборки и TestFlight QA.
