# Spider Wallet — UI/UX этап 1: кнопки и переключатели

Дата: 10 ноября 2026 г.  
База: `kepler-spider-main.zip` (загружен в чат).  
Формат: накладываемое накопительное ZIP-обновление для существующего `console-auto-unpack.yml`.

## Что реализовано

1. Создана общая дизайн-система кнопок в `Console/Design/WalletTheme.swift`:
   - `SpyderActionButtonStyle(.primary / .secondary / .tertiary / .destructive)`;
   - `SpyderChoiceButtonStyle(selected:)` для выбора без путаницы с настройками;
   - высота обычных CTA не меньше 52 pt; компактных действий — не меньше 44 pt;
   - общая форма Capsule, единые цвет/обводка и доступное disabled/pressed-состояние;
   - ранее используемый `.spyderPrimaryButton()` сохранён для совместимости с остальными экранами, но теперь тоже оформляется единой Capsule.
2. Кошелёк:
   - `«Активы / Криптовалюты»` → `«Портфель / Рынок»`;
   - главная CTA `«Подготовить перевод»`, так как универсальная отправка средств ещё не поддерживается;
   - `«Поддерживаемые активы»` вместо ложного обозначения реальных владений;
   - кнопки «Подготовить перевод»/«Получить» используют одинаковые правила размеров и контраста.
3. Отправка:
   - заголовок и описание различают предварительную проверку и отправку;
   - для неподдерживаемого сценария review возвращает к реквизитам вместо бессмысленного «отправить»;
   - показывается причина неактивного шага: отсутствует/неверный адрес, сумма или баланс;
   - выбор актива Ethereum приведён к menu, без конфликтующих segmented/menu контролов.
4. Получение:
   - вместо `Toggle` для одноразового согласия — прямое действие `«Показать адрес и QR»` после предупреждения о сети;
   - подписи сетей и сами селекторы увеличены; выбранный актив обозначен, в том числе для VoiceOver;
   - действия копирования/авторизации/проверки используют единые стили.
5. Чаты:
   - кнопки запроса/обмена реквизитами используют общую систему стилей;
   - новая контактная форма отличается основным действием `«Подключиться по коду»`, вторичным Spyder Touch, шарингом;
   - непостоянный фильтр «Показать скрытые» заменён с переключателя на кнопку-фильтр с выбранным состоянием;
   - улучшены подсказки для недоступных действий и доступные названия.
6. Настройки/профиль:
   - реальные постоянные переключатели сохраняют семантику Switch;
   - кнопки уведомлений и приватности унифицированы;
   - убрано ложное обещание выбора темы в строке настроек кошелька;
   - фильтры каталога получили интерактивные области не меньше 44 pt.

## Что НЕ менялось

Сетевые сервисы, кошельковые ключи, отправка транзакций, подписи, Face ID, чаты и их протоколы, Cloudflare Worker, backend API, хранилища, `project.yml` и workflow распаковщика.

Реальная отправка USDT в Ethereum остаётся доступна только по поддерживаемому сценарию защищённого чата с актуальным подписанным адресом/расчётом, как было в оригинальном коде. Отправка других монет не включалась.

## Как установить

1. Поместить ZIP `console-update-ux-stage1-20261110.zip` **в корень GitHub-репозитория** без ручной распаковки.
2. Убедиться, что в корне нет других `console-update*.zip`.
3. Запушить — `.github/workflows/console-auto-unpack.yml` обнаружит архив, наложит файлы на исходный репозиторий и удалит ZIP.
4. Запустить существующую iOS-сборку в GitHub Actions.

Обновление **накопительное относительно загруженного исходника**: содержит все изменения этого первого UX-этапа, но не дублирует неизменённые файлы репозитория.

## Проверки в этой среде

- `swiftc -frontend -parse` — синтаксис всех Swift-файлов `Console/` и `Tests/`: OK.
- `python3 ci/verify_ux_stage1.py` — 13 статических UX-регрессий: OK.
- Проверка ZIP на целостность и безопасные относительные пути: OK.
- **Не выполнялось:** Xcode typecheck/compile, iOS Simulator, живое взаимодействие на устройстве. Linux-среда не содержит iOS SDK. Итоговую работоспособность необходимо подтвердить сборкой.
