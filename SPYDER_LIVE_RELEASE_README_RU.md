# Spyder Wallet: накопительное обновление Live Wallet + 1:1 Chat

Это исходный код для следующей сборки TestFlight. **В контейнере не запускался Xcode и не выполнялся реальный Cloudflare deploy или App Store upload.**

## Что готово в коде

- Адреса Bitcoin (native SegWit), Ethereum и Solana формируются локально WalletCore после системной проверки доступа к кошельку; в UserDefaults сохраняются **только публичные адреса**, не сид-фраза и не закрытый ключ.
- Балансы BTC/ETH/SOL и USDT/USDC в сети Ethereum запрашиваются у публичных RPC, цены — у CoinGecko. Оценка портфеля показывает признак неполных данных, если сеть не ответила. Все запросы могут быть ограничены публичными провайдерами.
- Получение адресов / QR / explorer из существующего интерфейса.
- Чат 1:1: создание имени и уникального username, поиск @username, запрос контакта, принятие и отправка сообщений. В главном интерфейсе не нужно вводить серверный адрес; диагностика спрятана в «Профиль → Для разработчиков».
- Spider Devnet API и bearer token убраны с главной вкладки, доступны только из раздела для разработчиков.
- Кнопка «Отправить» честно сообщает, что **реальные трансферы пока недоступны**. Симуляция Touch не показывается среди главных действий.

## Установка

1. В корень `kepler-spider` загрузить только один архив с именем `console-update-spyder-live-release.zip`. GitHub workflow `Console — Auto Unpack Update` применит изменения.
2. Убедиться, что в GitHub Repository Secrets заданы **CLOUDFLARE_API_TOKEN** (доступ `Workers Scripts Edit` и Durable Objects), **CLOUDFLARE_ACCOUNT_ID** и действующие Secrets App Store Connect, которые уже обеспечили успешную Cloud Signing сборку.
3. **Вручную** заменить содержимое `.github/workflows/spyder-wallet-testflight-cloud.yml` отдельным `spyder-wallet-testflight-cloud-live.yml`. Распаковщик защищает `.github/workflows` и никогда не устанавливает туда YAML.
4. В GitHub Actions запустить **Spyder Wallet - Live Chat and TestFlight**. Новый workflow сначала развернёт Cloudflare Worker, запросит настоящий subdomain через Cloudflare API, проверит `/health`, внедрит URL в `Info.plist` и только потом запустит компиляцию, cloud signing и загрузку в TestFlight.
5. На **двух разных iPhone** создать раздельные профили @username, выполнить поиск, отправить запрос, принять его и проверить доставку сообщений.

Сервер не требует отдельной ручной настройки URL в приложении, **но должен успешно развернуться в Cloudflare**. Если Cloudflare Secrets отсутствуют или Worker недоступен, workflow завершится с ошибкой до создания нового iOS-архива. Это намеренное поведение, чтобы не повторять релиз с пустым чатом.

## Ограничения безопасности

- Сообщения хранятся в Cloudflare Durable Object в открытом виде. **Нет E2EE, multi-device восстановления чата и аудита.** Не передавайте через этот чат сид-фразы или секреты.
- Получение реальных криптоактивов на адреса не равно поддержке безопасной отправки. Отправка BTC/ETH/SOL/USDT/USDC пока намеренно не включена. **Не используйте существенные реальные средства до независимого аудита реализации ключей и транзакций**.
- Результаты проверки здесь: статический синтаксис всех Swift-файлов; Python unit tests, Node server tests, MessageChain tests; разбор YAML и Bash. Полную Xcode компиляцию подтверждает только GitHub runner.
- Версия вручную меняется в `project.yml`; номер сборки берётся из App Store Connect, следующий выше предыдущего. P12 не используется.
