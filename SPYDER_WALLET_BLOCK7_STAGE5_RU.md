# Spyder Wallet — Block 7 Stage 5: исходящие транзакции (проверка, не релиз)

## Что сделано

- `WalletEVMOutgoingTracker.swift`: read-only проверка *конкретной исходящей* EIP-1559-транзакции по хешу и ранее зафиксированному `WalletEVMUnsignedIntent`.
- Проверяются `chainId=1`, адреса отправителя и получателя/контракта, ERC-20 calldata, сумма ETH, `nonce`, `gas`, `maxFeePerGas`, `maxPriorityFeePerGas`, тип транзакции `0x2`.
- После майнинга проверяются квитанция, номер и хеш блока, канонический блок, status, подтверждения. Для успешной ERC-20-передачи дополнительно требуется правильный `Transfer`-лог токена с отправителем, получателем и количеством.
- В случае противоречия RPC алгоритм отказывает в подтверждении. Только две согласованные квитанции и не менее 12 подтверждений дают `.confirmed` / `.reverted`.
- `WalletEVMBroadcastStaging.swift`: проверка поведения транспорта с одним запросом. Код полностью исключён из обычной iOS-сборки с помощью `#if SPYDER_EVM_RELAY_TESTS`. Используется исключительно для изолированных тестов. Никакой автоматической отправки из Wallet UI **нет**.
- Две группы Swift-векторных тестов с подменёнными RPC и Python-проверки в CI.

## Критичные ограничения

**NO-GO для средств**. Этот этап не включает кнопку реальной отправки. Концепция тестового транспорта не даёт гарантий ни подписанного payload, ни независимого расчёта keccak256, ни сохранения запрета повторной отправки после перезапуска. Нельзя включать `SPYDER_EVM_RELAY_TESTS` в Release или TestFlight. Отсутствует продакшн-система блокировки nonce и восстановления отправки после перезапуска.

Также не выполнены: (1) компиляция всего iOS-проекта на Xcode 26.6; (2) нативный WalletCore signing-vector тест на macOS; (3) цикл on-device Testnet; (4) независимая проверка seed recovery; (5) самостоятельный security-review.

## Порядок проверки

1. Распаковать архив на точно совпадающую версию репозитория, которую вы используете для сборки.
2. Прогнать `python3 -m unittest discover -s ci/tests -v`.
3. Прогнать `swift test --package-path Packages/SpyderTerminalKit`, тесты MessageChain и server.
4. На macOS запустить `xcodegen generate --spec project.yml`, затем Xcode build-only и unit-test с Wallet Core (`WalletEVMSigningTests`).
5. Только после тестов подписания, nonce-защиты, последующего восстановления из Keychain и тестовых отправок на Sepolia рассматривать отдельный PR для реальной кнопки отправки.

Без приватных ключей и без реальных денег до прохождения всех этапов.
