BLOCK 3 — IMPLEMENTED IN SOURCE:
- Native List chat rows: decrypted-on-device last-message preview, timestamp, unread count,
  outgoing receipt marks, real recent online/typing state, mute/pin icons and persona label.
- Native swipe actions: pin/unpin and mute on leading edge; archive/restore and delete on trailing edge.
  Persona selection is inside the composer; row long-press offers Open and choose persona.
- Chats/Archive filter; hidden-chat recovery; pinned-first, then newest-first ordering.
- Per-owner pin/archive/delete state, preserved when changing mute/hide.
- Delete removes history from this account's view via monotonic clear boundary, not the other person's.
  Receiving/sending a new message restores the chat with the old clear boundary intact.
  Explicit reconnect also restores the initiator's conversation.
- Three statuses: server accepted = one tick; recipient device acknowledged after authenticated
  decryption = two ticks; visible incoming message acknowledged = two accent ticks.
  Fetching a preview/history alone does NOT imply read. APNs is NOT a delivery receipt.
- ACK target validation rejects sender/outsider/unknown-message and partial-invalid batches.
  Receipts are authenticated application acknowledgements stored by the relay, not signed
  cryptographic proof against a malicious relay. Existing TOFU E2EE trust model is unchanged.
- Read viewport checks exclude offscreen rows, terminal mode, Wallet tab, modal overlays,
  navigation disappearance and inactive/background app state.
- Ephemeral presence expires after 45 seconds, typing after 7 seconds. Foreground polling:
  chat about 3 seconds, chat home about 10 seconds; these are not WebSocket instant updates.
- Scoped conversation store: changing chat persona does not alter home-carousel selection.
  Selection is remembered for the originating persona/contact. Each identity pair keeps separate history.
- Composer chip: for this chat / only next message. Public contacts connect under selected persona
  if allowed. Private or restricted recipients may require explicit invitation for that identity first.
  Cross-server identity switching/sending is rejected. One-off sending does not load other persona plaintext.
- Contact/key-verification push page uses the actual scoped account.
- Terminal session resets on persona change; terminal-hidden chat cannot issue read acknowledgements.
- Plaintext cache invalidation prevents in-flight requests repopulating it after lock/background.
- All existing retained messages (up to 300 per pair) are reachable by the new history API;
  delivery ACKs are chunked at 100. This does not introduce unlimited archival storage or pagination.
