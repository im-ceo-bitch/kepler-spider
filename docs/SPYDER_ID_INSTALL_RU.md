# Spyder ID — установка и фактический статус

Этот пакет накопительный относительно исходного kepler-spider-main из чата.
В нём есть локальный сейф, три расширения iOS и интеграционная конфигурация.
Это исходный код, а не подписанная IPA. Сборка Xcode/устройство в этой среде недоступны.
Не считать пакет проверенным релизом до перечисленных ниже проверок на iPhone.

## Как установить

1. Загрузить один console-update-spyder-id-integrated.zip в корень репозитория.
2. Дождаться существующего Auto Unpack. Workflow в ZIP не входит и не меняется.
3. В Apple Developer → Certificates, Identifiers & Profiles:
   - основной App ID: com.spyder.wallet;
   - расширение AutoFill: com.spyder.wallet.id.autofill;
   - расширение Safari: com.spyder.wallet.id.safari;
   - расширение Share: com.spyder.wallet.id.share;
   - создать App Group: group.com.spyder.wallet.id;
   - назначить эту группу всем четырём идентификаторам;
   - включить AutoFill Credential Provider для приложения и AutoFill-расширения;
   - использовать одну Apple Team для всех целей.
4. Keychain Sharing уже объявлен в entitlements. Общая группа:
   $(AppIdentifierPrefix)com.spyder.wallet.id.
   Основная старая группа $(AppIdentifierPrefix)com.spyder.wallet сохранена для миграции.
5. Перегенерировать Xcode-проект обычным xcodegen generate --spec project.yml
   (существующий TestFlight workflow уже делает это).
6. Запустить unsigned Simulator build, XCTest, затем iOS archive/export с обновлёнными
   provisioning profiles. При ошибке подписи проверить App Group, App IDs и права API-ключа.

### Важный нюанс существующего workflow

Его архивирование глобально задаёт PRODUCT_BUNDLE_IDENTIFIER=com.spyder.wallet.
Поэтому CFBundleIdentifier каждого расширения записан явно в отдельный Info.plist;
имена модулей также заданы явно. При проверке архива убедиться, что PlugIns/*.appex
имеют три разных идентификатора выше, а версии/номера сборки равны приложению.
Проверить export cloud-signing отдельно — он в этой среде не запускался.
Проверяемая MARKETING_VERSION остаётся одна в project.yml.

## Первый запуск

- Кошелёк → Spyder ID → создать/открыть сейф → Face ID или код устройства.
- При обновлении с предыдущего патча записи мигрируют в общий зашифрованный контейнер.
  Старая зашифрованная копия оставлена для аварийного отката, новые записи пишутся только в общий сейф.
- Настройки Spyder ID → резервная копия → сохранить ключ отдельно → экспортировать файл.
- iPhone Settings → AutoFill & Passwords (название зависит от iOS) → включить Spyder ID.
- Safari → управление расширениями → включить Spyder ID, разрешить доступ к сайту.

## Safari

Вызов только из меню Safari, кнопка не встраивается в сам сайт.
Работает с доступными полями верхнего HTTPS-документа, не с чужими iframe.
Создать пароль: логин → карточка Spyder → Face ID → зашифрованный черновик → заполнение.
После регистрации снова открыть Spyder → мои аккаунты → подтвердить созданный пароль.
Если поле всё ещё доступно, подтверждение берёт актуальный пароль из него.
Если после генерации вы вручную изменили пароль, сохраните его через «Сохранить введённый
пароль» до исчезновения формы. Закрытую форму расширение восстановить не может.
Черновики видны и подтверждаются также внутри приложения. Автоматического заявления
«аккаунт создан» нет: расширение не может доказать успех регистрации любого сайта.
Сохранение введённого пароля создаёт отдельную запись, прежние пароли не перезаписываются.
Системное автозаполнение показывает подтверждённые записи, требует аутентификацию,
сопоставляет домен точно (поддомены не считаются эквивалентными автоматически).

## Документы и помощник

- Импорт PDF/изображений до 10 МБ, шифрование, просмотр, редактирование, экспорт выбранного файла.
- «Поделиться → Spyder ID»: PDF/фото, текст или ссылка → описание → Face ID → сохранить.
- Поиск по названию, логину, сайту, имени файла, категории и заметке.
- Распознавание изображения локально; для PDF извлекается текст первых пяти страниц.
  Сканированные PDF без текстового слоя сохраняются без выдуманных распознанных данных.
- Gemini: собственный платный API-проект/ключ в настройках помощника; модель редактируется.
  API-ключ компании не вшивается в ZIP. Ключ не предоставлен, живой вызов API не проверен.
  Отправляется только отдельно введённое описание после явного подтверждения;
  пароль, документ и извлечённый текст автоматически в облако не уходят.
  Ответ предлагает название/категорию, пользователь применяет их вручную.

## Что не заявлено реализованным

- Passkeys, OTP, автоматическая облачная синхронизация/семейный доступ: это отдельный следующий этап.
- Произвольный вызов поверх других приложений аппаратными кнопками iPhone.
- Гарантия работы на любой форме, внутри любого iframe или стороннего браузера.
- Автоматическое всплытие системной карточки сразу после отправки любой формы.
- Автоматическое восстановление без экспортированного файла и отдельного ключа.
- Независимый аудит безопасности и проверенная App Store/TestFlight-сборка.

## Проверки перед использованием

В этой среде выполнены: Swift grammar parse, JS syntax, 9 DOM-тестов заполнения,
структурная проверка XcodeGen/entitlements/plist/manifest, проверка ZIP.
Добавлены XCTest: roundtrip, подмена данных, неверный ключ, nonce, версия, генератор,
границы доменов, старый формат, валидация вложений. XCTest НЕ запускались.
Swift typecheck/Xcode build, Simulator, реальный iPhone, signing/export НЕ запускались.

На устройстве проверить:
1. Старый сейф → миграция → точность всех значений → перезапуск.
2. Отмена Face ID, код устройства, блокировка в фоне, редактор/экспорт при уходе в фон.
3. Все три вкладки, поиск, CRUD, пустые состояния, ошибки хранения.
4. Safari: новая регистрация, существующий пароль, изменённый пароль, несколько аккаунтов,
   переход на другой домен во время Face ID, отказ разрешений, неподдерживаемые формы.
5. QuickType/AutoFill в Safari и приложении с корректно связанным доменом.
6. PDF/фото через Share и Files, повреждённые/большие файлы, экспорт.
7. Backup на другом тестовом устройстве, неправильный ключ, конфликты, повреждённая копия.
8. Динамический шрифт на iPhone 13 mini/11 и iPad; Mac Catalyst отдельно (AutoFill не заявлен там).
9. Два клиента одновременно сохраняют записи — нет потерянных обновлений.
10. Архив содержит три .appex с правильными identifier/entitlement/версией.

Данные и ключи сейфа не связаны с seed-фразой кошелька. Не используйте этот ещё не
проверенный на устройстве пакет как единственную копию важных секретов.
